## 1. 背景与目标

用户要求规划一套空间机器人可视化仿真软件，约束为：

1. 平台 + 插件架构，机器人模型、动力学、环境设计、可视化引擎均可作为插件动态调用；
2. 开发环境采用 MSYS2 类环境、VSCode 编辑、语言不限、不同组件可用不同语言；
3. 可打包运行于 Windows 与 Linux。

目标是形成可实施、可验证、可演进的架构基线，并给出技术栈与交付路径。

## 2. 方案要点

### 2.1 平台 + 插件

- 内核最小化：只负责调度、注册表、数据总线、时间/坐标系、插件宿主与故障处理。
- 场景依赖**能力**（如 `srsp.dynamics/solver@>=1.0`）而非插件 ID；同一能力允许多实现，按优先级/用户固定选择。
- 插件生命周期：发现 → 校验 → 依赖解析 → 加载 → 配置 → 运行 → 卸载；支持暂停态重配与检查点恢复。

### 2.2 标准数据与调用接口

| 层 | 载体 | 用途 |
|---|---|---|
| 调用 | 纯 C ABI（进程内）+ gRPC（边车） | 同一 `method + payload` 语义 |
| 消息 | Protobuf | 控制、元数据、小消息 |
| 数组 | Arrow C Data Interface | 状态、矩阵、图像、点云，零拷贝 |
| 模型 | SRM（JSON + GLB） | 浮基、轮/CMG、推力器、柔性、传感器安装 |
| 场景 | glTF 2.0 + 扩展 | 网格、材质、实体映射、灯光 |
| 记录 | MCAP | 自包含、可索引、可回放、Foxglove 直开 |

### 2.3 进程与语言

- v1 单进程（Studio = UI + 内核 + 默认插件），但接口按可跨进程设计，后续可拆 `srspd`。
- C/C++/Rust 走进程内 C ABI；Python/C#/Java/MATLAB/Julia 走 gRPC + 共享内存边车。
- Python 不内嵌，规避 MinGW/MSVC ABI、GIL 与崩溃传染。

### 2.4 领域能力

- 动力学：浮基多体（CRBA/ABA）、轮/CMG 动量交换、推力器、GJK + 顺序冲量接触与捕获。
- 环境：CSPICE 星历、EGM2008 球谐引力、NRLMSISE-00 大气、SRP、IGRF、eclipse 与光照共享。
- 传感器：IMU、星敏、太阳敏感器、相机、LiDAR、GNSS、F/T、编码器；噪声使用确定性随机流。
- 渲染：bgfx 为主（多 RHI、BSD），Qt Quick 3D 兜底；双原点 + 反转 Z 解决轨道尺度抖动。

### 2.5 工程与交付

- Windows：MSYS2 UCRT64 + CMake Presets + Ninja；Linux 共用同一套构建配置。
- 打包：可重定位 runtime、`.srpkg` 插件包、Inno Setup / AppImage / deb、依赖收集与冒烟测试。
- 路线：M0 契约与骨架 → M1 最小闭环 → M2 环境与传感器 → M3 捕获与交付 → M4 Beta。

## 4. 风险与待确认

| 项 | 说明 | 处理 |
|---|---|---|
| 柔性附件是否进入 v1 | 影响动力学接口与验证范围 | 当前 v1 不做，1.1 引入 |
| 渲染器顺序 | bgfx 优先还是 Qt Quick 3D 优先 | 待评审（可视化是核心卖点，倾向 bgfx） |
| Linux 首发包 | 是否首发提供 AppImage/deb | 当前 M3 提供 |
| Python 支持矩阵 | 3.11–3.13 还是包含 3.14 | 待确认依赖 wheel 情况 |
| 数据分发 | 地球纹理/高精度星历内置或可选包 | 当前基础包 + 可选高清包 |

主要风险：自研动力学数值验证、bgfx 驱动兼容、MSYS2 缺包、边车延迟、插件 ABI 稳定性。应对见 `docs/07` 风险登记。
