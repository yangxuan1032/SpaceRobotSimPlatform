- 日期：2026-10-23
- 状态：已确认（D-13～D-16 按建议采纳，文档已同步落地）
- 提出人：用户
- 关联文档：[仿真工具调研](2026-10-23-simulator-landscape.md)、[M0 执行计划](2026-10-22-m0-execution-plan.md)、[07 路线图](../../../docs/07-roadmap-risks.md)、[04 技术栈](../../../docs/04-subsystems-and-stack.md)、[01 架构](../../../docs/01-architecture.md)

## 1. 背景

调研结论（[2026-10-23-simulator-landscape.md](2026-10-23-simulator-landscape.md)）三条：

1. 「多体+接触 + 空间环境 + 实时可视化 + 插件生态」的一体化开源平台确实存在空白；
2. 最接近的竞品是 **mjorbit（MuJoCo + 航天器扩展）** 与 **Isaac/MJX 生态**，其优势在接触质量与 GPU 吞吐；
3. 高精度轨道工具之间也只有**米级一致**（Basilisk vs GMAT/Orekit 实测 0.02–1.2 m，特定工况 7–72 m 分歧），说明"可信"来自**公开的对照方法与容差表**，而非绝对精确。

当前进度：M0 阶段 1（契约）基本完成，四工具链各 4/4 测试通过；内核/CLI/CI 未建。

## 2. 优化原则

| # | 原则 | 落到规划上 |
|---|---|---|
| P1 | 不打 GPU-RL 吞吐 | v1 非目标（已写入 01 §1.3）；互操作替代竞争 |
| P2 | 「能看/能录/能回放」是生命线 | M1 出口判据不可裁剪，延期即降级其它范围 |
| P3 | 可信度靠公开基准 | 精度对标脚本入库、容差表进文档、基准报告随版本发布 |
| P4 | 借力成熟引擎 | 高保真接触走 MuJoCo 边车；自研聚焦刚性与确定性 |

## 3. 里程碑调整（建议）

### 3.1 M0（收尾，约 2 周）

| 原计划 | 调整 |
|---|---|
| 含 Qt 空壳 | **移出到 M1**（空壳本身不产生用户价值，且 M1 要按最终形态重做：窗口 + 句柄 + `renderer.null`） |
| 内核骨架、CLI、CI | 保留，且为 M0 唯一出口项 |
| — | 新增：`tests/bench` 骨架（哪怕只有空壳 + 一个基线数字），为 P3 铺路 |

### 3.2 M1（最小闭环，8 周）

| 新增/加固 | 内容 | 验收 |
|---|---|---|
| **可视化不可裁剪** | 场景树/属性/时间轴/视口 + 双原点渲染 | 服务星接近目标星场景 10 分钟 60 fps |
| **录制/回放不可裁剪** | MCAP 录制 + 回放 | 回放 10 分钟 `state_hash` 一致 |
| **互操作 W7（新增）** | ① `dynamics.mujoco` 边车原型（借用接触质量）② MJCF → SRM 导入器（只读子集）③ 导出：MCAP/glTF | 同一模型在 rigid 与 mujoco 下趋势一致（容差内）；MJCF 样例可导入 |
| **精度对标 W7** | 与 Pinocchio 的 `M/h/J` 对比脚本 + 双体轨道解析解 | 脚本可复现，偏差表入库 |
| Qt 空壳（从 M0 移入） | 窗口 + 句柄 + `renderer.null` | 空壳启动即验证句柄传递链路 |

### 3.3 M2（环境与传感器，8 周）

| 新增/加固 | 内容 |
|---|---|
| **环境对标（P3）** | `env.spice` 与 Orekit/GMAT 同工况对比：位置/速度偏差表、eclipse 时刻偏差；脚本入库 |
| **容差表成文** | 在 03 文档补「容差分级」：跨工具米级、跨平台相对 1e-6、同平台位级 |
| 传感器 | 相机/IMU/星敏，噪声按 `(seed,id,seq)` 复现 |
| SDK | Python SDK 走 `core_api`，替代直连边车 |

### 3.4 M3（接触/捕获与交付，8 周）

| 调整 | 内容 |
|---|---|
| 接触策略 | 自研「刚性 + 基础接触」与 MuJoCo 边车「高保真接触」**双轨**，同一场景可切换对比 |
| 交付 | 安装包、`.srpkg`、签名、8h soak（原计划不变） |
| 基准报告 | 发布前出「性能 + 精度 + 互操作」三张表（P3 落地） |

### 3.5 1.1（演进，非 v1 承诺）

- **FSW 对齐**：定义与 Space ROS 的接口映射（可选桥接插件），把「飞行软件可复用」作为对外卖点；
- 柔性附件、面元 SRP、MuJoCo 正式支持（原 1.1 项保留）。

## 4. 新增工作流 W7：互操作与基准

| 任务 | 产出 |
|---|---|
| W7.1 MuJoCo 边车 | `plugins/dynamics_mujoco`（边车）+ 对照场景 |
| W7.2 MJCF 导入 | `model.mjcf` 导入器（子集：body/joint/actuator/geom）→ SRM |
| W7.3 导出 | SRM → MJCF（可选）、MCAP → Parquet/CSV |
| W7.4 基准套件 | `tests/bench/`：动力学步进、边车延迟、回放一致性、精度对照 |
| W7.5 报告生成 | 脚本产出 markdown/图表，随版本归档 |

## 6. 决策项

| 编号 | 决策 | 建议 | 影响 |
|---|---|---|---|
| D-13 | Qt 空壳是否移出 M0 | **是**，M1 按最终形态做 | M0 范围收缩，出口更快 |
| D-14 | MuJoCo 边车是否列为 M1 必做 | **是**（原型级即可） | 借接触质量，避免自研长尾 |
| D-15 | 是否对外发布精度/性能基准报告 | **是**（M2 起每版本） | 建立可信度，工作量增加约 1 人周/版本 |
| D-16 | 是否把 MJCF 导入列为 M1 必做 | 建议 M1 做只读子集，完整导入 M2 | 互操作是差异化的一部分 |

## 7. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| M1 范围膨胀 | 可视化 + 录制 + 互操作同时压进来 | 互操作只做「原型 + 最小子集」；可视化优先 |
| muJoCo 边车性能 | 进程间延迟 | 先用批量步进（`step_batch`），M2 再优化 shm |
| 基准报告拖期 | 报告需对照工具环境 | 先固定脚本与容差表，报告可后置但不能缺席 |
| 与竞品正面比较的舆论风险 | 指标选择不当会被反驳 | 只发布可复现的指标（同工况、公开脚本），不排名 |
