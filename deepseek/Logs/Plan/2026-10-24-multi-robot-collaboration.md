# 方案：多机器人协同工作支持

- 日期：2026-10-24
- 状态：已确认（v1 范围内新增能力，文档同步中）
- 提出人：用户
- 关联文档：[01 架构](../../../docs/01-architecture.md)、[02 插件契约](../../../docs/02-plugin-contract.md)、[03 数据契约](../../../docs/03-data-contracts.md)、[07 路线图](../../../docs/07-roadmap-risks.md)

## 1. 背景与现状

用户要求：**平台必须支持多机器人协同工作**。

现状盘点：

| 维度 | 现状 |
|---|---|
| 多实体同场 | 场景状态 `repeated EntityDelta entities` 已支持（[03 §4.1](../../../docs/03-data-contracts.md)） |
| 多航天器/星座 | 仅作为 C11 预留（[07 §11](../../../docs/07-roadmap-risks.md)），无实现计划 |
| 协同层（编队/任务分配/一致性） | **空白** |
| 机器人间通信 | **空白**（无拓扑、延迟、丢包模型） |
| 分布式跨进程集群 | v1 非目标，1.2 由 `srspd` 承担（[07 §9](../../../docs/07-roadmap-risks.md)） |

结论：场景数据模型够用，但「协同」所需的**通信模型、协同控制能力、确定性调度顺序**三项缺失。

## 2. 范围界定

| 范围 | 包含 | 不包含 |
|---|---|---|
| **v1（M2–M3）** | 单进程内 N 个机器人（N ≤ 8 起步）× 共享宏步；显式通信拓扑与延迟；协同控制器能力；多机器人可视化与录制回放 | 跨进程/跨机分布式、真实无线信道仿真、大规模（>32）集群 |
| **1.2** | `srspd` 远程内核，多进程分担机器人 | 云端弹性伸缩 |
| **1.3+** | 大规模集群、集群强化学习对接 | — |

## 3. 设计要点

### 3.1 场景与团队模型

```jsonc
"entities": [
  { "id": "robot_a", "model": "models/sat_a.srm", "initial_state": { } },
  { "id": "robot_b", "model": "models/sat_b.srm", "initial_state": { } }
],
"teams": [
  {
    "id": "team_1",
    "members": ["robot_a", "robot_b"],
    "links": [
      { "from": "robot_a", "to": "robot_b", "delay_ns": 100000000,
        "bandwidth_bps": 9600, "loss_rate": 0.0 }
    ]
  }
]
```

规则：

- `robot_id` 即实体 `id`，全局唯一；
- 链路是**有向边**，`delay_ns` 为整数纳秒（与时间契约一致），`loss_rate` ∈ [0,1]；
- 未声明的链路视为不可达。

### 3.2 确定性调度顺序

1. 一个宏步内：**按 `robot_id` 字典序**依次更新各机器人的动力学；
2. 协同层（`coordinator`）在**所有单体更新之后**运行一次，读取 `team.state`，输出下一位指令；
3. 链路消息投递按 `(发送时刻, 发送方 id, 序号)` 排序，与墙钟无关；
4. 每个机器人的随机数种子 = `xxh3(global_seed, robot_id)`，保证并行/串行结果一致；
5. 上述顺序写入 `state.meta.schedule_order`，回放时校验。

> 这条规则是协同确定性的一部分：调度顺序变了，`state_hash` 就会变，必须显式记录。

### 3.3 通信模型（`srsp.io/link@1`）

| 参数 | 语义 |
|---|---|
| `delay_ns` | 单程延迟，整数纳秒 |
| `bandwidth_bps` | 速率上限，超出时排队 |
| `loss_rate` | 丢包概率（按确定性随机源） |
| `queue_capacity` | 队列上限，溢出即丢最新 |

消息进入**事件队列**，在下个或后续宏步按时间戳投递；回放时重放同一事件序列。

### 3.4 协同能力（`srsp.control/coordinator@1`）

| 方法 | 语义 |
|---|---|
| `team.describe` | 返回成员、拓扑、任务描述 |
| `team.update` | 输入 `team.state`，输出各成员的 `cmd.actuator` 与任务分配 |
| `team.status` | 返回任务进度、约束满足情况 |

首版实现放在示例插件里（编队保持：期望相对位姿 + PD），不进入内核。

### 3.5 数据契约

- 新增话题 `team.state`：每机器人位姿/速度摘要 + 链路状态 + 任务分配；
- 新增话题 `link.message`：链路消息与投递结果（用于分析与回放）；
- 两者进入 MCAP 录制，回放时不重算协同，只重放结果（可选重算模式）。

### 3.6 可视化

- 编队连线（按链路延迟着色）、成员标签、协同任务分配箭头；
- 团队级时间轴：同时显示 N 个机器人的关键指标。

## 4. 里程碑调整

| 里程碑 | 新增内容 | 验收 |
|---|---|---|
| M2 | 双机器人协同 demo：2 机器人 + 1 条链路 + 编队保持 | 编队误差 < 0.1 m（10 分钟）；`state_hash` 回放一致 |
| M3 | 3+ 机器人协同 + 抓持协同 + 链路异常（丢包/延迟抖动） | 丢包 5% 下任务完成；异常链路有诊断 |
| 1.2 | `srspd` 多进程分担机器人 | 跨进程 `team.state` 一致 |

## 5. 验收指标

1. 2 机器人编队保持 10 分钟，相对位姿误差 < 0.1 m / 0.5°；
2. 100 ms 链路延迟下，编队仍收敛（超调 < 20%）；
3. 5% 丢包下任务完成率 ≥ 90%；
4. 同一场景重复运行 10 次 `state_hash` 完全一致；
5. 4 机器人时单步耗时 ≤ 2× 单机器人（线性度检查）。

## 6. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 状态规模爆炸 | N 机器人 × 状态量 | 起步限 8 个；性能基准纳入 CI |
| 调度顺序影响结果 | 顺序不同 → 不同结果 | 顺序显式记录 + 回归测试 |
| 链路模型过度设计 | 真实信道复杂 | 首版只做延迟/带宽/丢包三参数 |
| 协同算法侵入内核 | 内核变重 | 协同只作为插件能力，内核只提供 `team.state` 与调度 |
