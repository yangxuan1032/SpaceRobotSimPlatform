## 1. 总体节奏

```

 4 周              8 周               8 周                8 周               6 周
```

## 3. 里程碑与出口标准

### M0：契约与走通骨架（4 周）

**目标**：证明"平台 + 插件 + 跨语言 + 双平台"的最小链路成立。

| 交付物 | 验收 |
|---|---|
| `api/`：C ABI 头、proto、manifest schema、SRM schema v0 | 评审通过，`static_assert` 布局测试通过 |
| `hello` 插件（C++ 进程内）与 `hello` 边车（Python） | `srsp-cli demo` 两种传输输出一致（用例在 `<model>/ModuleTest/integration`，分层见 02 §10.3） |
| 内核骨架：注册表、调度循环、日志、诊断、插件宿主 | 能加载/卸载/配置插件，错误路径有测试 |
| CMakePresets + `bootstrap-msys2.sh` + CI（Win/Linux） | 干净机器按文档 30 分钟内构建成功 |
| `tests/bench` 骨架与首版基线数字 | 至少 1 个可复现基准（含容差表占位） |
| 文档：01–05 初稿 | 团队评审，待定项收敛 |

> Qt 空壳已移入 M1（2026-10-23 规划调整）：空壳本身不产生用户价值，且 M1 要按最终形态（窗口 + 原生句柄 + `renderer.null`）重做，避免二次返工。

**出口判据**：新成员按 README 从零构建成功；CI 绿；双传输 demo 可复现。

### M1：最小可用闭环（8 周）

**目标**：能加载一个空间机器人模型，在轨道环境里跑起来、看得见、录得下。

| 交付物 | 验收 |
|---|---|
| SRM 1.0 + URDF 导入器 + 3 个示例模型 | 质量特性/拓扑校验通过；导入报告完整 |
| `dynamics.rigid`：浮基 + 关节 + 轮 + 推力器 | 与 Pinocchio 对比 `M/h/J`：同编译器同 flags 下相对误差 < 1e-10；跨平台按 1e-6 容差（见 03 §2.5） |
| 力模型：球谐引力、第三体、SRP、大气 | 双体轨道 1 圈误差 < 1 m；能量漂移达标 |
| `renderer.bgfx`：机器人 + 地球 + 星空 + 太阳光 | 1080p 60 fps；轨道尺度无抖动 |
| `srsp-studio`：场景树、属性、时间轴、视口 | 可加载/播放/暂停/单步/选中 |
| Qt 空壳（自 M0 移入）：窗口 + 原生句柄 + `renderer.null` | 空壳可启动，句柄传递链路可查 |

## 4. 关键路径与依赖

```
ABI/数据模式 ──▶ 内核调度 ──▶ 动力学 ──▶ 传感器闭环 ──▶ 捕获
      │              │            │
      └──▶ 渲染器 ───┴──▶ UI ─────┘
                 │
                 └──▶ 录制/回放 ──▶ 分析/回归
```

- **最长路径**：契约冻结 → 动力学 → 传感器闭环 → 捕获 → 交付。
- 渲染器与 UI 可并行，但依赖"场景协议"冻结（M0 末）。
- 打包与 CI 必须从 M0 开始，不能留到最后（历史经验：打包问题会反噬架构）。

## 6. 质量门禁

每个里程碑必须同时满足：

- [ ] 单元测试通过率 100%，核心模块覆盖率 ≥ 70%
- [ ] 契约一致性测试全绿（进程内 + 边车）
- [ ] 性能基准不劣化超过 15%
- [ ] 无 P0 缺陷；P1 有修复计划
- [ ] 文档与代码同步（CI 校验示例可解析）
- [ ] 在干净环境完成一次安装/运行冒烟
- [ ] 许可与第三方清单更新

### 11.3 约束

- 预留能力在 manifest 与文档中统一标注 `reserved`；未实现前被调用返回 `SRSP_E_UNSUPPORTED` 并在诊断中提示所需版本；
- 预留只使用「能力 ID + ABI 追加位 + 既有字段承载」，不得为此改动已冻结的结构；
- 触发条件未满足的能力不排期，避免范围蔓延（见 R6、R15）。

### 12.1 性能豁免说明（2026-10-26）

两轮时间盒（执行计划 C3）已用完，结论如下：

| 轮次 | 尝试 | 结果 |
|---|---|---|
| 1 | ABA（铰接体算法，O(n)） | 与 `M⁻¹(τ−h)` 不一致（12 分量全错，约 2×），整体回退（P26） |
| 2 | 质量矩阵列裁剪（只算祖先链有效列） | 功能等价（34/34）但更慢：2.09 → 3.71 ms（P32），回退 |

**结构性结论**：9.06 ms 中质量矩阵装配约 2.1 ms，其余主要是 RK4 每步 4 次 306×306 LDLT。只要保留「稠密 M + 分解」架构，任何 M 级微优化都无法达到 300 µs（差距约 30×）。

**处置**：300 µs 从 M1 移出，作为 **1.1 性能里程碑**（需 ABA 或等价的 O(n) 前向动力学）；M1 保留「基准可复现 + 差距记录」。当前 CPU 实现作为 1.x 基线。

## 17. 集群术语边界（2026-10-27）

gpt 设计包把“分布式集群”列为 v1 非目标；本项目的 M4 计划包含“单机多 world 批量”。两者不冲突，但必须把术语钉死：

| 术语 | 定义 | 状态 |
|---|---|---|
| **单机批量** | 一个进程内、一个 GPU/CPU 后端上并行推进 N 个 world | **计划内**（M4） |
| **跨机分布式** | 多台机器各自运行 world，通过网络同步状态/事件 | **非目标**（1.x 不做） |
| **云端多用户** | 多租户、鉴权、会话隔离 | **非目标** |

任何文档提到“集群”时必须指明是“单机批量”还是“跨机分布式”。
